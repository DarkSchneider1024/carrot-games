## 2. 測試方法

### 2.1 解析度

| 代號 | 解析度 | 測試內容 |
|---|---|---|
| desktop | 1920×1080 | 發牌與第一手（德州撲克打完 1 手） |
| laptop | 1366×768 | **完整一輪**：大老二與麻將打到結算，德州撲克打 4 手，再切到豪客場打 1 手 |
| tablet | 1024×768（觸控） | 發牌與前兩手 |
| phone-landscape | 844×390（手機橫向） | **完整一輪**（內容同 laptop） |
| phone-portrait | 390×844（手機直向） | 先看轉向提示，關掉後以直向畫面打前兩手 |

### 2.2 自動對局機器人

機器人所有操作都透過真實點擊：選牌、出牌、PASS、吃碰槓胡、打牌、跟注、加注、下一局。開發模式才會掛上 `window.__carrotQA`，這個 hook 只用來**讀取**引擎狀態、決定要出哪一手，不會直接改動遊戲。

機器人同時檢查以下流程問題：
- 引擎狀態連續 12～15 秒沒有變化（卡死）
- 輪到玩家時，出牌和 PASS 都被拒絕
- 引擎在等玩家動作，畫面卻沒有更新
- 本局已結束，卻沒有出現結算畫面
- 頁面 JavaScript 錯誤（`pageerror`）

### 2.3 卡片版面檢查

每個檢查點會掃描所有可見的撲克牌、麻將牌與動作按鈕：

| 規則 | 嚴重度 | 判定方式 |
|---|---|---|
| `viewport-clip-x` / `viewport-clip-top` | 高 | 卡片超出畫面左右邊或頁面頂端 |
| `partially-clipped` / `hidden-by-overflow` | 高 | 卡片被 `overflow` 容器切掉一部分或整張 |
| `occluded` | 高／中 | 在卡片上取 5 個點，用 `elementFromPoint` 檢查是否被其他 UI 蓋住 |
| `needs-page-scroll` | 中 | 手牌或按鈕在第一個畫面以下，要捲動才看得到 |
| `hidden-in-scroll` / `scroll-edge-cut` | 中 | 卡片藏在可捲動的容器裡，或在容器邊緣被切 |
| `content-overflow` | 中 | 牌面文字超出卡片框 |
| `overlaps-other-card` | 低 | 卡片有 3 個以上取樣點壓在另一張卡片下 |

以下情況不算破圖：
- 設計上的全螢幕遮罩（轉向提示、結算視窗、規則視窗）
- 玩家自己打開的面板（聊天框、聽牌提示），只在對應檢查點排除
- 暫時出現的氣泡與 toast
- 對手蓋牌疊放造成的重疊（刻意設計）

在修正前的數據中，轉向提示遮罩共造成 57 筆，本報告的「修正前」數字已先扣除。

## 4. 修正內容

### 4.1 版面（`big-two.css`、`mahjong.css`、`poker.css` 全部改寫）
- 所有選擇器都加上頁面根類名（`.bigtwo-page` / `.mahjong-page` / `.poker-page`），解決 L1。
- 大老二與麻將頁面改為 `100dvh`：
  - 牌桌用 `grid-template-areas`（上 / 左、中、右 / 手牌）固定每一家的位置（L2）。
  - 卡片尺寸依畫面寬高自動計算：`--card-w: min(clamp(…vw…), (100dvh - …) / …)`。
  - 從 390px 高的手機橫向到 4K，全部內容都在第一個畫面內（L6）。
- 手牌列不再使用 overflow 容器，改為保留卡片上移的空間，選起的牌不會被切（L3）。
- 手機直向時，大老二手牌改成扇形疊放，麻將手牌改成換行。
- 聊天框改由上方工具列的 💬 開啟，預設收合；螢幕寬度 ≥1880px 時才在牌桌外側展開（L4）。
- 玩家名牌移到動作列旁邊，不再蓋手牌（L5）。
- 麻將：
  - 河牌改成四家各自一區，並自動縮小牌面讓全部牌都放得下，不再捲動（L7）。
  - 顯示四家的副露與花牌。
  - 牌面改用文字加 CSS 繪製（萬紅、筒藍、條綠、白板藍框），不再依賴字型是否有麻將 emoji（L11）。
- 德州撲克：
  - 贏家改成公牌下方的橫幅，不蓋座位；贏的 5 張牌會發光（L8）。
  - 寬螢幕時盲注設定與戰報移到側欄，動作列一定在第一個畫面內（L9）。
  - 座位置中改用 `translate`、放大動畫改用 `scale`，兩者分開寫，不會再互相覆蓋（L10）。
  - 新增莊家、小盲、大盲標記；新增底池加注與 ALL-IN 按鈕。
- `char_carrot.png` 從邊緣做 flood fill，把低飽和度的棋盤格背景改為白色，角色本身不受影響（L12）。這張圖不需要重新生成，所以沒有用到 gemini-mcp。

### 4.2 流程與規則
- 三款遊戲的引擎都改成事件驅動（`engine.onUpdate`），移除輪詢。
- 引擎內加上局數 token 並提供 `destroy()`，換局或離開頁面後，舊的 AI 計時器不會再觸發（F4、F6）。
- 大老二（F1–F5）：
  - 修正結算的索引錯誤。
  - 比較牌型前先排序，並依台灣規則判定順子大小（23456 > A2345 > 10JQKA，JQKA2 不算順子）。
  - 強制第一手包含 ♣3。
  - 「全打完排名」模式在所有人 PASS 後，出牌權交給正確的玩家。
  - 修正角色名稱對應；出牌失敗時顯示具體原因（例如「首輪出牌必須包含 ♣3」「必須出相同張數」）。
  - 新增 💡 提示按鈕，由 AI 建議要出哪幾張。
- 麻將（F6–F9）：
  - 保留 16 張不摸，摸完即流局，由莊家連莊。
  - 搶牌依「胡 > 碰槓 > 吃」及座位順序處理。
  - 支援明槓、暗槓、加槓，槓後從牌尾補牌。
  - 新增自摸胡按鈕與結算視窗（顯示胡牌手牌、台數明細、四家分數變化），並自動輪莊或連莊。
  - 摸到的牌放在手牌最右邊；最後一張打出的牌會發光。
  - 台數規則擴充：門清自摸、全求人、正花、小三元/大三元、圈風與門風、小四喜/大四喜、碰碰胡、混一色/清一色/字一色、海底撈月、河底撈魚、槓上開花。
- 德州撲克（F10–F13）：
  - 修正 `ReferenceError`。
  - 引擎會驗證每個動作是否合法，CHECK 與 CALL 依應跟金額只顯示其中一個。
  - 實作最小加注規則與邊池結算。
  - 全員 ALL-IN 後自動發完公牌，每一步都會更新畫面。
  - 開局時跳過沒有籌碼的座位；未登入玩家籌碼歸零時發放救濟金。
  - 籌碼與戰績只在每手結束時同步一次。

## 5. AI 優化

以下數據由 Node 模擬器取得：AI 直接驅動引擎，舊 AI 的邏輯原樣移植到模擬器中當作對照組。

| 遊戲 | 新 AI 策略 | 模擬規模 | 結果 |
|---|---|---|---|
| 大老二 | 先把手牌拆成最少手數的組合（最多搭配兩組五張牌型），並減少低單張；出牌時先打弱的組合，保留「沒人壓得過」的控制牌；跟牌時評估壓牌會不會拆壞牌型，決定要不要 PASS；有人剩 1～2 張時優先用大牌擋 | 每種模式 200 局，新 AI 兩席對舊 AI 兩席 | 快殺模式新 AI 勝率 **68.5%**（舊 31.5%）；全打完模式 **71.0%**（舊 29.0%）；每步最多 18ms |
| 麻將 | 用向聽數計算搭配有效進張數選擇打牌；吃碰槓只在能減少向聽數或拿到台數牌時才喊；對手副露多或牌牆快摸完時，改打安全牌防守；暗槓與加槓不會讓牌變差才槓 | 600 局（對調座位各 300 局） | 新 AI 胡牌 **445 局**，舊 AI 17 局，流局 138 局；每步最多 190ms（模擬時同時跑 QA 搶 CPU，實際更快） |
| 德州撲克 | 用蒙地卡羅模擬（250～350 次）計算對現存對手的勝率，搭配底池賠率決定動作；翻牌前後用不同門檻；下注金額依底池比例，並會詐唬與半詐唬；三位 AI 風格不同：兔兔謹慎、貓咪激進、熊熊均衡 | 兩種盲注各 600 手 | $10/$20：新 AI **+5,685**，舊 AI −5,685；$50/$100：新 AI **+43,136**，舊 AI −43,136；每步最多 7ms |

模擬中同時驗證：
- **大老二：** 10 個牌型與順子大小斷言全部通過；400 局都正常結束。
- **麻將：**
  - 3,000 手隨機建構的胡牌都能判定為胡；3,000 手隨機手牌的 `checkWin` 結果與舊版一致。
  - 每一步檢查牌數總和固定為 144 張。
  - 每局分數變化總和為 0；AI 胡牌的手牌都是合法胡牌。
  - 另以「人類 API 流程」跑 80 局，全部正常結束。
- **德州撲克：**
  - 新的快速評估器與舊版（窮舉 21 種組合）比較 20,000 次攤牌，牌型與勝負結果 **0 差異**。
  - 每手結束時籌碼守恆；共 36 手出現邊池。

## 7. 已知限制與後續建議

- **手機直向的扇形疊牌**本來就會互相遮住，可能記到 `overlaps-other-card`（低）。每張牌的中央仍可點擊。
- **麻將台數**尚未計算平胡、三暗刻以上、搶槓，也沒有八仙過海、七搶一。台數以常見規則為主。
- **德州撲克上排座位的動作氣泡**（例如「🚀 加注到 $120」）在 1366×768 時可能有一半被頂部工具列蓋住。氣泡是暫時提示，不影響牌面，所以 QA 不列入計算；可以考慮把上排座位的氣泡改放在座位下方。
- **德州撲克的 ALL-IN 加注**：金額不足最小加注時，引擎仍會重新開放其他玩家行動（簡化處理，正規規則不應重新開放）。
- **QA 截圖用的是 Headless Chromium。** 麻將已不依賴 emoji 字型；角色名稱裡的 emoji 仍由系統字型顯示。
- **打包體積：** `vite build` 的 chunk 超過 500 kB。這個警告在本次修改前就存在，建議之後用動態 `import()` 拆分各遊戲。
- **尚未測試：** 線上對戰模式、Firebase 登入後的籌碼同步。本次 QA 只測 AI 對戰。
